= Module 2: Deploy the MCP Tools
:navtitle: Deploy the MCP Tools

== Objective

Deploy the Intel MCP tools server and call each tool directly to see the structured data the agent will use.

== Exercise 1: Deploy the MCP Server

Deploy the solution-tools pod in your namespace:

[source,bash,role="execute",subs=attributes+]
----
oc project {project_name}
oc project -q
----

[source,bash,role="execute",subs=attributes+]
----
cat > /tmp/apply-triforce-201 <<'SH'
#!/usr/bin/env bash
set -euo pipefail
manifest="${1:?manifest}"; source_route="${2:?source route}"; short_route="${3:?short route}"
base="https://raw.githubusercontent.com/rhpds/triforce/f484cb66c3dcddff323df8814f637dc92c73c179/infrastructure/manifests-201"
export SOURCE_ROUTE="$source_route" SHORT_ROUTE="$short_route"
curl -fsS "$base/$manifest" | python3 -c '
import os, sys
text = sys.stdin.read()
source = "kind: Route\nmetadata:\n  name: " + os.environ["SOURCE_ROUTE"] + "\n"
target = "kind: Route\nmetadata:\n  name: " + os.environ["SHORT_ROUTE"] + "\n"
if text.count(source) != 1:
    raise SystemExit("expected exactly one pinned Triforce Route marker")
sys.stdout.write(text.replace(source, target, 1))
' | oc apply -f -
SH
chmod 0700 /tmp/apply-triforce-201

/tmp/apply-triforce-201 solution-tools.yaml solution-tools tools
----

The helper downloads only the pinned Triforce revision. It preserves the
Deployment, Service, selectors, ports, image digest, probe, and Route target;
only the Route object's name becomes the short Launchpad alias. The short name
keeps the generated OpenShift hostname within its DNS-label limit.

Wait for the pod to be ready:

[source,bash,role="execute",subs=attributes+]
----
oc rollout status deploy/solution-tools --timeout=60s

export MCP_URL="http://solution-tools:8095"
----

The Terminal runs inside your assigned namespace, so it calls the Service
directly. This avoids depending on the cluster's edge certificate and keeps
the tool exercise inside the seat boundary. Do not add `-k` or
`--insecure`; the browser-facing Route remains available to the platform, but
it is not needed for these Terminal calls.

== Exercise 2: List Available Tools

The MCP server exposes tools via JSON-RPC 2.0 -- the same protocol used by Claude and VS Code:

[source,bash,role="execute"]
----
MCP_URL="http://solution-tools:8095"
curl -fsS -X POST "${MCP_URL}/mcp" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":"1","method":"tools/list","params":{}}' \
  | jq '.result.tools[] | {name, description}'
----

== Exercise 3: Intel Hardware Lookup

Look up Intel Xeon 6 processors optimized for AI inference:

[source,bash,role="execute"]
----
MCP_URL="http://solution-tools:8095"
curl -fsS -X POST "${MCP_URL}/mcp" \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc":"2.0","id":"2",
    "method":"tools/call",
    "params":{"name":"intel_hardware_lookup","arguments":{"family":"xeon6","use_case":"ai_inference"}}
  }' | jq '.result.structuredContent'
----

== Learning Outcomes

* MCP tools return structured data in milliseconds -- vs seconds for an LLM call
* Tools provide information the model should not invent: sourced product specifications, platform capabilities, and illustrative architecture patterns
* Workshop recommendations are not validated customer sizing. Confirm current specifications, availability, compatibility, and performance requirements with Intel and Red Hat.
* The JSON-RPC 2.0 protocol is the same one used by Claude, VS Code, and other AI systems -- it is an industry standard
